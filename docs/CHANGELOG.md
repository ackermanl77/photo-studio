# Changelog

Fix history moved out of `docs/PROJECT_STATUS.md` (which now holds only the current architecture
and open issues). Newest first. Entries describe the code as it was then: modules, entry points and
docs they name may since have been removed (for example `app/frontend.py` and the other per-feature
frontends, `app/project.py`, `app/edit_stack.py`, `app/cached_processing.py`, and the old
`docs/workflows/` guides, deleted on 2026-10-03 as superseded by `docs/USER_GUIDE.md` and
`docs/PROJECT_STATUS.md`).

## 2026-10-09 -- Spanish interface, fonts, 16-bit precision, smaller fixes

- **Interface language:** an English/Español selector next to the uploader (`app/i18n.py`, catalog
  `app/i18n_es.py`); the on-canvas editors' buttons, hints and accessibility labels follow it too.
- **Fonts (`app/fonts.py`):** a Font choice for every Text layer and for the watermark -- the fonts
  installed on this computer plus .ttf/.otf/.ttc files added under Layers > 🔤 Fonts (stored in
  `user_data_dir()/fonts`); stored by name, with "(not installed)" and the default font where a
  project's font is missing.
- **B4, 16-bit precision:** HSL, Vibrance, Color Grading, Texture, Sharpen and film grain now compute
  in float in a 16-bit export (their 8-bit output is unchanged), and a 16-bit TIFF keeps the EXIF and
  GPS sub-IFDs.
- **Smaller fixes:** rotated Ellipse shape layers; "Closed Path" resets after Add Path Layer; Magic
  Wand Sample size; a Clipping margin for the clipping warning; Library rescans import XMP sidecars
  changed by another program (the catalog records each sidecar's modification time); the curve
  editor keeps extra points off another point's X.

## 2026-10-07 -- F13 feature gaps, code signing (still version 0.2.0, not tagged yet)

- **Tone and colour (F13):** Whites/Blacks sliders, per-channel R/G/B tone curves, and a Black & White mixer.
- **Repair → Heal (`app/heal.py`):** the best-matching nearby patch per spot, Poisson-blended with
  `cv2.seamlessClone`; falls back to inpaint at the border or for huge regions (~0.7 s for three spots at
  24 MP).
- **Layer masks** from Masks selections.
- **History list:** the 📌 popover lists the last 30 Undo steps, each named after what it changed
  (`EditHistory.steps()`/`describe_change()`); a click jumps there through `_pending_restore`.
- **Lens → "From the photo's lens" (`app/lens_lookup.py`):** EXIF camera/lens/focal/aperture looked up
  in lensfun (optional `lensfunpy`, `requirements-raw.txt`, pinned in `constraints-cpu.txt`) and the Lens
  sliders least-squares fitted to its correction fields (~3/4 of a zoom's distortion field). The
  desktop build bundles lensfun's database and `--self-test` requires it (`lensfun_lenses`, 1304 lenses).
- **R2:** System Health shows the logs folder and opens it. **T5:** `.github/workflows/perf.yml` runs the
  24 MP budgets on Windows weekly and on demand.
- **Code signing:** `build_release.ps1 -Sign` takes the thumbprint from `-CertificateThumbprint` or
  `CODESIGN_THUMBPRINT`, checks the certificate and finds signtool before the build, signs
  `PhotoStudio.exe` with an explicit thumbprint and timestamp (`CODESIGN_TIMESTAMP_URL`, default DigiCert),
  and with `-Installer` passes Inno Setup a `codesign` tool so `PhotoStudio.iss` signs the installer and its
  uninstaller. Verified with a self-signed test certificate: a real `-Installer -Sign` build signed and
  timestamped the exe, the uninstaller and the installer.

- **P4 remainder:** Temperature/Tint on an 8-bit image is three per-channel lookup tables (the
  same float32 products, bit-identical; 0.21 -> 0.03 s at 24 MP) and a single broadcast multiply in
  16-bit mode; Highlights/Shadows computes its shift as `new_base - base` with in-place weights,
  only for the side in use (0.83 -> 0.66 s; at most 1 level apart from before). The guided filter
  stays exact: a subsampled "fast guided filter" would save another ~0.2 s but shift the base by
  up to ~1 level and make previews and exports differ slightly.

- **B6 remainder: face-aware skin smoothing.** Portrait's new "Only around detected faces"
  (`portrait_faces_only`, on by default) multiplies the skin-tone mask by feathered ellipses
  around the faces YuNet finds on the image being edited (`face_region_mask()`), so skin-coloured
  backgrounds stay sharp; with no face found it falls back to the global mask, so photos without
  faces (and the golden images) are unchanged. Tested on the public-domain portrait with a
  skin-coloured patch beside it.

- **F8 remainder: XMP sidecars** (`app/xmp_sidecar.py`). The Library reads `xmp:Rating` (-1 =
  rejected) and `dc:subject` keywords from a photo's sidecar when it catalogues the photo for the
  first time, and with "Also write ratings and tags to XMP sidecars" writes every rating, reject and
  tag change back (`IMG_0001.xmp` beside RAW files, `photo.jpg.xmp` beside others; an existing file
  with either name is used). Rewriting keeps the rest of an existing sidecar, its namespace prefixes
  included (tested with a Lightroom-style `crs:` sidecar).

## 2026-10-02 -- optional CUDA export, installer fixes

- **Opt-in CUDA export resize/sharpen.** `app/gpu_export.py` resizes and output-sharpens the final
  export on the GPU when the GPU pack's torch (or a CUDA torch in a source install) is available:
  Export settings "Use GPU for export resize/sharpen", the Batch Processor's "Use GPU for profile
  resizing", and the CLI's `--gpu-export`. Off by default; file encoding stays on the CPU, and a
  missing or failing CUDA logs a warning and falls back to the CPU path. Tests cover the opt-in
  validation, the CLI flag, 8- and 16-bit exports through the GPU transform, the CPU fallback and the
  batch option; `resize_and_sharpen()` hands torch a writable array, silencing PyTorch's read-only
  warning. Checked on an RTX 5080: a 4500x3000 -> 2048 px Screen-sharpened export matched the CPU
  path to a mean of 0.35 levels (max 4), 202 ms vs 305 ms once warm; the first call pays ~8 s of
  CUDA start-up.
- **Installer fixes, found by building it and installing/uninstalling silently.**
  `build_release.ps1 -Installer` also finds a per-user Inno Setup (`%LOCALAPPDATA%\Programs\Inno
  Setup 6`). Setup always demanded admin rights; it now allows a per-user install
  (`PrivilegesRequiredOverridesAllowed=commandline dialog`: an "all users / just me" choice in the
  wizard, `/CURRENTUSER` on the command line). The "delete your data?" uninstall question used
  `MsgBox`, which a silent uninstall can't suppress; `SuppressibleMsgBox` answers No (keep the data).
  An empty `HKCU\Software\Classes\.photoproject` key is no longer left behind.

## 2026-10-02 -- remaining "important" roadmap items (P1, F3, F11, B4)

`tests/test_interaction_improvements.py` and `tests/test_high_bit.py` cover these. No golden image
changed: the default 8-bit path is byte-identical (`tests/test_parity_golden.py` passes unregenerated).

- **Refine-on-pause (P1).** A proxy-previewed photo is re-rendered at full resolution once the edit
  has been unchanged for 1.2 s (`app/refine_preview.py::RefineTracker`). The render runs in a
  background thread (so the next slider move isn't blocked behind it) on the backend's new "refine"
  lane, which any newer interactive request of the same session supersedes (`app/backend.py`
  `_cancellation_check()`), so an obsolete job stops at its next pipeline step. A small `st.fragment`
  status line polls (`run_every`) only while a refine is pending and reruns the page when it lands
  (deferred to the end of the script via `_request_rerun()` during a full run). The refined image then
  drives the canvas, histogram and Save (no second full render). The two-stage cache is untouched;
  ordinary reruns still render the proxy.
- **Drag-to-pan (F3).** At 100 % and above the canvas is `ui_editors._pan_viewer_html()`: drag (or
  arrow keys) and the new view center is committed through the zoom navigator's own hidden text_area,
  so Python handles it exactly like a navigator click. Pan values keep 4 decimals (slider step
  0.0001) -- a drag at 400 % moves a few source pixels, below the old 0.01 step.
- **Keyboard in the editors (F11).** Crop: arrows nudge the focused corner or the box by one source
  pixel (Shift 10). Pen: arrows move the selected anchor, Alt+arrows its handle, Delete removes it.
  Curve: Up/Down on a focused point. Paint: `[`/`]` brush size, arrows move the last radial/gradient
  (Alt: its end point; it is repainted from a snapshot of the mask taken before it). A burst of key
  presses commits once (`KEY_COMMIT_DELAY_MS`) through the existing hidden text_area. All editors
  have `role="application"` and aria labels. The JavaScript is tested under Node with a fake DOM
  (`tests/js_fake_dom.js`).
- **16-bit output and a float32 pipeline path (B4, partial).** New `bit_depth` option (8/16) and
  export setting: `decode_source(..., high_bit=True)` decodes 16-bit PNG/TIFF (OpenCV, EXIF
  orientation applied) and RAW (rawpy `output_bps=16`) to float32; `PhotoProcessor` gains a
  high-precision mode (an `hdr` array behind an `image` property) where geometry/lens, exposure,
  brightness, contrast, highlights/shadows, temperature/tint, saturation, curve, clarity, mask
  blending, crop and the post-crop vignette compute in float, and every other step's 8-bit change is
  carried onto the float data. `encode_export()` writes 16-bit PNG (OpenCV + spliced iCCP/eXIf
  chunks) and 16-bit TIFF (tifffile, zlib, ICC + IFD0 text tags), with resize (Pillow Lanczos on
  float channels), output sharpening and watermark. Wired through the backend (`export.bit_depth`
  implies the float run), the Export panel ("Bit depth", saved in export presets), the CLI
  (`--bit-depth 16`) and folder batch. Not done: a linear-light working space for every step and float
  versions of HSL/vibrance/grading/texture/dehaze/denoise/sharpen/layers/portrait/grain.

- **Projects keep layers editable (B10).** `.photoproject` now stores the Layers tab's stack
  parametrically (`layers/stack.json`) with each Image layer's pixels as its own PNG entry

  and saveable export presets (`export_presets.json` in the user data folder). Ctrl+E saves.

  pin every package at the versions the suite last passed with; `requirements.txt` has upper bounds,
  declares `tifffile` directly and no longer lists the unused scikit-image or pytest (now in
  `requirements-dev.txt`). CI runs Windows and Ubuntu x Python 3.12/3.14 plus a real RAW (DNG) decode
  job; `release.yml` runs the CI workflow first (`needs: test`) and builds with Python 3.14. The

- **Generated test images (T3/T6).** The tests no longer read the third-party wallpapers/Facebook
  photos in `tests/assets` (or the mangled `sample.png`); `tests/synthetic_assets.py` generates
  photo-like images, a 16-bit gradient and a real CFA DNG. The files themselves were then deleted
  (they remain in git history).
- **16-bit grayscale decode (B7).** `I;16`/`I`/`F` images are scaled to 8 bits instead of clipped
  (a 16-bit gradient PNG used to decode ~99.6 % white). RAW decodes with `HighlightMode.Blend`.
- **One supported-format list (R3).** `app.raw_import.SUPPORTED_EXTENSIONS`/`uploader_types()` feed the
  main uploader (now including .raf/.rw2/.orf/.pef/.srw), Batch, Library and the CLI; a photo over the
  backend's upload cap is refused up front with a clear message.
- **Real-ESRGAN (P7).** Tiled inference (512 px, 32 px overlap, 256 px tiles when free VRAM is low), a
  process-wide inference lock, `torch.inference_mode()`, `torch.cuda.empty_cache()`, and a verified
  weights download (SHA-256, atomic) -- `ai_upscale.download_weights(progress)` /
  `weights_present()`.
- **Local backend hardening (R1/B11).** A per-launch token (`PHOTO_BACKEND_TOKEN`, header
  `X-Photo-Token`) is required by `/process` when set -- the desktop launcher and the frontend's
  on-demand start both set one; the desktop picks free ports per launch, holds a single-instance mutex
  (focusing the existing window), and shows a native error dialog on a startup failure. The frontend
  restarts a dead backend once, logs a standalone backend's output to `logs/backend-standalone.log`,
  and tags interactive requests with its session + a generation: the backend abandons a superseded
  render between pipeline steps (409). Denoise/dehaze run under a semaphore (`PHOTO_MAX_HEAVY_JOBS`);
  the backend serves on waitress when it's installed.
- **Stage 1 by handle (P3).** The backend keeps the last few Stage 1 results and returns a handle;
  Stage 2 sends the handle instead of re-uploading the lossless PNG (falls back to the upload on a
  410), and the frontend caches the response PNG as-is instead of decoding and re-encoding it.
- **Clarity and Highlights/Shadows (B5).** Clarity is luminance-only midtone local contrast with a
  radius of ~1.2 % of the long edge (it used to be the same global operation as Contrast);
  Highlights/Shadows works on an edge-aware (guided-filter) base layer of luminance, keeping detail
  and avoiding halos. Both are resolution-independent.
- **Geometry (F4/B9).** Rotate 90° left/right, flip, a Straighten slider with "Auto" level (Canny +
  Hough), numeric Left/Top/Width/Height crop fields, a Custom W:H ratio and a swap-orientation toggle;
  "Constrain crop" (on by default) crops away the black/smeared borders of distortion, keystone and
  straighten. `app/geometry.py::apply_geometry()` is shared by the pipeline and the frontend's
  Crop/Masks/Repair base image.
- **Exposure in EV and -100..100 units (F2).** Exposure is now in stops applied in linear light with a
  soft highlight shoulder; Contrast, Saturation and the mask targets are -100..100. Saved recipes are
  version 2; version-1 recipes (presets, projects, imports) migrate automatically
  (`app.edit_schema.migrate_legacy_keys()`). Every main section has a "↺ Reset" button.
- **Per-mask adjustments (B8).** A Masks selection can carry its own adjustment set (exposure,
  contrast, saturation, temperature, tint, clarity), sent as `local_masks` + `local_adjustments`;
  selections combine by add/subtract/intersect; Radial selections expose center/radius/feather.
- **Canvas (F3).** Fit / 100 % (a true 1:1 crop of real pixels) / 200 % / 400 % (pixels enlarged, not
  resampled), and a click-to-center navigator while zoomed.
- **Image layers (F5).** Placed with position/scale/rotation and kept in proportion (they were
  stretched to the canvas); Text size is a % of the short edge; Layer Style/stroke pixel sizes scale
  with the render, and layers are rendered at the proxy's size for previews (P1). The watermark uses the
  same TrueType font as Text layers.
- **Batch (F7).** Every supported format, straight from the uploaded bytes (two uploads with the same
  name used to overwrite each other in a never-deleted temp folder), results streamed into a ZIP under
  the user data folder, and a Stop button.
- **Library (F8).** The catalog shows without a rescan, as a cached thumbnail grid (RAW via its
  embedded preview) with "✏️ Edit" to open a photo in the editor; RAW files are catalogued; a rescan no
  longer resets ratings and tags.
- **Streamlit 1.64 features (F1/F11).** The tool tabs report which one is visible and hidden tabs
  skip their display-only work (editor iframes, thumbnails, face detection); Undo/Redo use native
  `shortcut=` (the injected JavaScript is gone), plus Z (1:1/Fit), B (before/after), G (grid), Ctrl+E
  (save). Mask overlays can be hatched or outlined, not only coloured.
- **Parity and golden images (T4), budgets (T5), suite speed (T7).** Every recipe control is checked
  to reach the pipeline, every pipeline option to be read by it, the CLI against the backend on a full
  option set (new CLI `--options FILE`, `--exposure-ev`, `--rotate`, `--straighten`,
  `--constrain-crop`), and seven golden images by PSNR (`PHOTO_REGENERATE_GOLDEN=1` to regenerate).
  `PHOTO_PERF_TESTS=1 pytest -m perf` runs 24 MP budgets. AppTest tests are marked `slow`.
- **Smaller fixes along the way.** Auto Enhance is image-adaptive (F10); film grain is
  resolution-independent; Undo history is capped at 200 steps and the full-resolution caches expire
  after an hour (P5); Remove GPS is on by default and Export Multiple Sizes has the toggle too (R4);
  one `preview_image` implementation (B12); the on-canvas editors' HTML builders moved to
  `app/ui_editors.py` (F14, partial).

- **Full ICC profile conversion and soft proofing — the last two items on the "what would a professional editor do" gap list.** Previously the app just preserved whatever `icc_profile` bytes a file happened to carry, unlooked-at, and applied every tonal/color operation as if the pixels were already sRGB — for a wide-gamut source (Adobe RGB, ProPhoto RGB, a camera's own profile) that's subtly wrong: colors that were correct under the wider profile look oversaturated once treated as sRGB.   Soft proofing deliberately does **not** simulate an external printer/press profile — what that usually means in Lightroom/Photoshop needs a calibrated profile file (e.g. a press house's own `.icc`) this offline-first app has no database or bundled copy of (the same "no real profile database" limitation already true of Lens Profiles above). - **The one item deliberately deferred out of the vector-shapes work above: a true Bezier-curve Pen tool.** Shape layers (Rectangle/Ellipse/Line/Polygon/Star) covered named primitives; this adds a fourth layer kind, `"path"` -- arbitrary anchor points connected by cubic Bezier curves, closed or open, each point independently draggable and each with its own curve handle.
  - **Math**: new functions in `app/vector_shapes.py` -- `path_outline_points()` samples every consecutive anchor pair's cubic Bezier segment into a fine polyline (`_cubic_bezier_points()`, 24 steps per segment; PIL's `ImageDraw` has no native curve-fill/curve-stroke primitive, so every curve is rasterized as short straight segments, the same approach OpenCV's own drawing functions use internally), plus one more segment closing back to the first anchor when `closed`. Each point is `{x_pct, y_pct, handle_dx_pct, handle_dy_pct}` -- one handle, stored as an offset from the anchor, used *symmetrically* as both that point's incoming and outgoing tangent (a "smooth point" in every vector editor's own terms) -- not independent, non-mirrored in/out handles (Photoshop's Alt-drag "corner point," a real, documented gap in "Known Issues"). A zero-length handle degenerates its Bezier segment to a perfectly straight line, so corner-only paths are still fully expressible. `render_path_layer()` renders the sampled outline via `draw.polygon()` (closed: can fill and/or stroke) or `draw.line()` (open: stroke only -- there's no well-defined "inside" to fill without a closed boundary).

Anchor/handle dots are plain absolutely-positioned `<div>`s (percentage left/top), not SVG circles inside a percentage-viewBox SVG -- a 100x100 viewBox stretched with `preserveAspectRatio="none"` onto a non-square display box would visually squash circles into ellipses; only the connecting path/handle-guide-lines (which don't need to be perfect circles) use that simpler percentage-viewBox SVG. The "add a point" click listener is attached to the background `<img>` element specifically, not the whole wrapper `<div>` -- the dots are siblings layered on top of it, not descendants, so a click landing on one of them never bubbles into "add a new point here" the way attaching the listener to a shared ancestor would have.
